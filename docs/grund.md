# GRUND-skopos: project memory needs empirical feedback

Skopos supplies evidence for improving how software agents acquire project
knowledge. Addressable specifications and small files are useful mechanisms;
their effect on actual tasks must still be measured. The project is an
experiment, with no established claim of cost savings or improved correctness.

Grund owns declared knowledge and its citations. Rhei owns workflow identity,
outcomes, and measured accounting. Fissile owns file-size gates. Skopos owns
observations of context acquisition and derived, explicitly noncausal reports.
The checked repository remains the memory; the local ledger is evidence.

## 1. Evidence before optimization

A tool return is evidence of returned content, not proof of model submission,
attention, necessity, or causal use. Repeated reads are candidates for review,
not automatically waste. No correlation authorizes removing a specification,
skipping required instructions, rewriting context, or merging source files.

## 2. A prototype earns further scope

Start with offline import and small machine-readable reports. A daemon, live
hooks, automatic retrieval, and memory editing require demonstrated utility.
Compare changes on held-out executable tasks against cheap static alternatives,
including citation-based navigation, lexical retrieval, and git co-change.
